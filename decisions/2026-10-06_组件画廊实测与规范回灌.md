# 组件画廊实测与规范回灌（gallery.html → V0.2）

> 触发：把 V0.2 渲染成一份**组件画廊 + 检查台**（`gallery.html`），作为规范的首个真实渲染验证面；外部 Claude 按 §7.2 十一维评审给出 38 条；逐条本地复核后**反向回灌规范**。
> 日期 2026-10-06 · 状态约定 DECIDED / EXPLORING / DEFERRED / REJECTED
> 结论先行：**本次最大发现不是"我写错了什么"，而是 §4 组件集对真实界面覆盖不足**——表格 / 导航 / 空状态 / 表单控件 / 状态标签在规范里没有规则，画廊被迫按 token 现推。已把这些**实测成立、只引用既有 token** 的组件规则回灌 §4，另记 3 条新观察点。**未改任何色值 / 字号 / 圆角 / 间距数值**，走"未升版补遗"。
> 立场修正（HAE 指示）：初版规范非圣旨；对外部批评先默认采纳、除非有具体理由不采；认的直接改。

## 0. 这次测试到底验了什么

- **载体**：`gallery.html`（组件画廊 + V0.2 检查台），亮 / 暗 × 4 accent 全组合渲染，含按钮八态、表格、Modal、命令面板、代码块、空状态、骨架屏、流式光标。
- **外部输入**：Claude 11 维评审 38 条。

- **可复算纪律**：未新增任何未经本地复算的对比度数值；状态 tint 以"派生规则"写入而非声称具体比值。

## 1. 回灌进 §4 的组件规则（核心增量）

规范 §4 组件表原本只覆盖：主/次/文字按钮、输入框、用户消息、AI 回复、选中态、标签 Chip、资产卡、代码块、Modal、骨架屏。画廊实测暴露**缺 5 类**，且都是任何真实界面必用的：

| 缺项 | 画廊里的实测处置 | 回灌要点 |
|---|---|---|
| **表格 Table** | 表头 secondary 小字、气声分隔线、元数据右对齐、选中行 tint+左 accent 条 | 明确单元格**上下内距对称**、表头须留呼吸（踩坑点，见 §6） |
| **导航 Tabs / 分段 / 分页 / 面包屑** | 选中项 = 实色 accent（分段/胶囊）或 accent 2px 下划线（tab） | "当前项"只用 accent 表达，禁止第三种颜色 |
| **空状态 Empty** | 无插画无堆色、一句说明 + 一个主操作 | 靠文案与非颜色通道成立 |
| **表单控件 Switch / Checkbox / Radio** | 选中态用 accent；禁用 opacity .5 + 非颜色提示 | 错误/成功描边沿用输入框（accent→danger/success） |
| **状态标签 Chip（补）** | 成功/警告/错误 chip = 状态色 ~12% 叠 surface 作底 + 状态色作字 | 只有"选中"才用实色 accent |

- **原因**：这些不是"新野心"，是规范本就该定义、只是没写到的部分；画廊已把它实现且通过 token 校验，属于**"规范补齐到已被实现的事实"**。
- **红线自证**：回灌的是**文字规则**（§4 本就是组件规则表），不是 CSS / 可导入组件库；不触 §5 DEFERRED 红线。

## 2. §2.4 暗色前景说明补齐

- **发现**：4 套 accent 只给了亮色 ink / tint；暗色下"accent 做文字 / 图标"仅铁锈定义了 `--accent-text`（`#D9754F`），其余三套画廊自行推导（克莱因蓝 #7E97E0 / 蒂芙尼青 #81D8D0 / 祖母绿 #4FB99B）。
- **处置**：§2.4 增补一句暗色自适应说明；**具体提亮值不写死**，列入 §9.14 观察——一个画廊页 ≠ 真实暗色产品，不提前定值（守"不预先改规范"）。

## 3. 新增 §9 观察点（本次实测浮出）

## 4. 确认有效（测试背书、无需改）

- **字重两档 400/600 够用**：画廊曾用 500/650，删掉后零损失 → 反证两档纪律成立。
- **单 accent / 气声描边 ≤1.3 / 圆角仅 10·6 / 间距走刻度**：渲染全程守得住，未出现"守不住"的场景。
- **Motion L0–L3 足够一个复杂页**：画廊含 Modal、命令面板、骨架、流式，全落在 L0–L3，未感到需要 L4 → 给 §9.9 一个正向数据点（护栏目前够用）。

## 5. 驳回的外部批评（附理由；是"规范此刻这么定 / 撞硬规则"，非"它错了"）

Claude 38 条里，本地复核后**不采纳**的：

- **骨架屏 1.2s"过长"**：§4 钦定值，画廊照渲染正是供你判它偏不偏长，非 bug。
- **选中行用 accent"违反强调只走字重"**：§4 选中态本就 = 实色 accent + Semibold；此条引错条款（"只走字重"讲正文强调）。
- **hover 升 L1"违反 Shadow Budget"**：L1 定义即"可交互卡"，且一次只一张、瞬时，非"20 张同亮"。
- **Modal 240ms"偏慢"**：§5.2 L3 允许 250–400ms，240 在下限之下。
- **拆外部 CSS"利用缓存"**：撞单文件产物约定 + §5 DEFERRED 红线；本地双击打开的自检页无缓存收益。
- **`syncHex` "未缓存"**：仅点击时跑几次、非逐帧，伪性能问题。

其余 Claude 提的**字号 / 字重越界、缺态、响应式、Hero 说明书语气、检查闭环**等——**采纳并已改**（见 `gallery.html` R2）。

## 6. 本次实现踩的坑（→ 已转成 §4 规则）

- **表头 `th` padding-top = 0**，文字顶到面板上边线（HAE 截图指出）。根因不是手滑，而是**规范从没写表格 / 单元格的垂直内距与表头对齐**。已把"单元格上下内距对称、表头留呼吸"写进 §4 表格规则，避免下游重犯。

## 9. 追加 · 用户通读反馈（R3）

用户在检查台 13 项全部点"通过"后，通读 gallery 全篇又给出两点反馈——**恰好说明"全通过"不等于"没问题"，通读本身是另一层验证**。

**① 全篇信息密度偏高**
- 判定：非画廊故意，是规范问题。§4 页面级间距封顶 48，对长展示页偏密（正是 §9.12 挂着的观察点，被这次通读坐实）。
- 处置：gallery 展示 section padding 提到 64、hero 96、head 与内容间距 32、栅格 gap 24；检查台刻意保持 48（工作面比展示面密，做出 Density↔Breathing 节奏差）。§4 补 `64 / 96` 页面级档；§9.12 更新为"已补档、仍待第 2 项目确认"。

**② 四套 accent 观感排序：铁锈≈蒂芙尼 > 祖母绿 > 克莱因蓝**
- 诊断（本地复算，非主观）：
  - 克莱因蓝 `#002FA7` 做小字 对纸 **9.48:1** —— 对比够，问题是**过饱和 + 冷蓝压在暖纸上振动** → 阅读障碍。
  - 祖母绿 `#009473` 做小字 对纸 **3.4:1** —— **直接不达 AA**（需 ≥4.5）。
  - 铁锈 / 蒂芙尼观感好，因为 §2.4 **给了它们深墨 ink**（`#7A2E1A` / `#0A7680`）。
- 根因：§2.4 对克莱因蓝 / 祖母绿只写"白字直用"（那是**块上前景**），**漏定义小字 `--accent-ink`**，逼下游拿高饱和原色做小字，既违反本系统"绝不用高饱和 accent 做小字"、又造成上述观感问题。用户排序 = 这个缺口的直接投影。
- 处置：gallery 里克莱因蓝 `--accent-fg` → `#24355C`（低饱和深海军蓝，10.7:1）、祖母绿 → `#0B5C47`（7.1:1）；§2.4 补两行 ink 值 + "ink 列=小字色、块上前景另取"说明。块色暂不动。
- **待用户定**：克莱因蓝的"块"色 `#002FA7` 是否保留。A 保留 + 已补深墨（小字已不刺眼）；B 整块换降饱和蓝（如 `#2E4C7E`：纸 7.6 / 白字 8.6 / 落暗底 2.2，顺带缓解 §9.5）；C 从四套移除、换别的 temperament。
- **裁决（终）**：用户又提供 Color Hunt 配色（`#3368A0` / `#66A3BF` / `#C8DFDB` / `#F2EFE7`）。本地复算后**只借 `#3368A0`**（饱和 52%、白/accent 5.8、落暗底 3.2，优于我上轮手挑的 `#2E4C7E`）；`#66A3BF` 钢青（白字 2.78 不达标、偏青离蓝身份）与 `#C8DFDB` 浅鼠尾草（跨色相、不能作蓝 tint）不采纳；`#F2EFE7` 奶油 ≈ 本系统纸 `#F4F1EA`，反证配色相性。最终：克莱因蓝块色 `#002FA7` → **钴蓝 `#3368A0`**（ink `#2A4E7A`、tint `#DCE8F4`、块上白字），slot 改名"钴蓝（原克莱因蓝）"。§9.5 由"近乎不可见"升级为"基本解决（1.7→3.2，达 3:1 图形阈值）"。已同步 gallery、§2.4 表、§9.5、修订记录。
