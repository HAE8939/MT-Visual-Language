> 结论先行：**这是一份高质量的通用视觉方法论，正好补我留白的短板**；但它面向"画面"（含图片/人物/海报），与 HAE 的"数字产品 UI 系统"部分重叠、部分冲突。**采纳其"负空间操作层 + 感知测试 + 冲突优先级"改造进 §7.4 / §8.1；拒绝其字号尺寸范例（与 HAE 刻意收小的字阶正面冲突）与通用色彩六分法（HAE §2 语义 token 更细）。**

## 0. 我的短板诊断（诚实）

- 我此前处理"太密"的方式是**把 padding 数字调大**（48→64→96）——这恰是 Codex §3.3 点名的错误：留白不是调数字、不是缩小，而是 删除·合并·移动·拉开·给主体呼吸区。
- 更根本：我全篇**均匀密度**（每屏都是等重面板堆叠、大量 50/50 分栏），缺 §3.2"大块连续负空间"和 §7"密度节奏（禁全 MEDIUM）"。**数字调对了，结构没变**——所以你还是觉得密。
- 教训：留白是**结构问题**不是**数值问题**。

## 2. 不采纳 / 冲突（附理由，非"它错"而是"与 HAE 定位不合"）

- **§4.2 尺寸范例"标题 48 / 副标题 20 / 正文 14 / 辅助 11"**：与 HAE §3"字号阶梯刻意收小、Display ≤32、禁超大字做层级、无 11px"正面冲突。HAE 层级靠字重+对比、不靠字号跨度——两套哲学。**只取其"尺寸要成阶梯、有主次"的原则，数值用 HAE 自己的。**
- **§5 色彩角色六分法（PRIMARY/SECONDARY/ACCENT/…）**：HAE §2 语义 token 更细（canvas/surface/ink/accent/tint/border/status…）且单-accent 纪律更严；不引入通用六分法造成双轨。仅吸收 §5.4"小面积高饱和=高视觉重量"（强化 accent 纪律）。
- **§2.4 网格 / §15 十段输出格式**：HAE 已有 §4 间距·对齐纪律与 §8.2 打分卡，不重复；§15 对纯 UI 页偏重，不采纳（保留精简的感知测试）。
- **整体定位**：Codex 面向"画面"，HAE 面向"产品界面"；构图类条款按 UI 语境裁剪。
