# MT-Visual-Language

HAE 个人 AI 产品设计系统 · 唯一真源仓库。

这里存放的不是某个产品的代码，而是一套**跨项目复用的 UI 设计语言 + 设计质量标准**：任何项目要做界面，先来这里读规范。目标是让 MT-Deck、博客、未来的 AI 工具在视觉上像"同一家人"——纸感背景、单一高饱和 accent、气声描边、无阴影、层级靠字重与对比度；同时不满足于"统一"，用一套质量标尺和自检闭环，把界面从"干净但模板味"推到"高级、有品牌表达"。

## 设计哲学

- **规范即资产。** 每一条 token、每一句"为什么"，都是从几十套配色里逆向、复算出来的判断，不是拍脑袋。它该被版本化地沉淀、长期复用，而不是散落在各项目的临时样式里，每做一次界面就重新发明一遍。

- **真源只有一个。** 下游项目只写一行指针引用这里，不复制全文。要改就回到这里改、升版——一处定义，处处一致。规范才不会在每个项目里各说各话、悄悄漂移成几十种样子。

- **克制即纪律。** 界面上只留一个原色，仓库里也只留必要的东西：首个真实项目验证前拒绝生成 CSS / Tailwind / CI，先让规则本身经受真实项目的验证。少，是为了让每一个像素、每一条规则都站得住。

- **纯文本即自由。** Markdown 加 Git。能读、能 diff、能被任意 AI 编程助手直接投喂，不锁定任何平台。工具会过时、平台会关停，一份纯文本里的审美判断可以活很久，而且始终属于你。

- **可复算即可信。** 每个对比度、明度、饱和度都有出处、能重新算出来。这让系统既能被信任，也能被继承——后来者不必膜拜结论，而能顺着证据自己判断、继续往前走。

## 起源

对开源项目 [nevertoday/rime-color-scheme](https://github.com/nevertoday/rime-color-scheme)（MIT）做**设计逆向分析**：解析其全部 40 套配色方案（20 主题 × 浅色/夜色）的 YAML 色值，提炼出可迁移的设计规律——

- 品牌原色在浅色/夜色中一个字节都不改（20/20）
- 全画面只允许一个高饱和色，其余皆为带色温的中性灰
- 层级用对比度分档（正文 ≈11:1 / 次级 ≈4.5:1 / 描边 ≈1.15:1），不靠字号与粗线
- 暗色分层用半透明白叠加代替阴影（源夜版为单层约 7%；本系统继承并扩为规范 §2.3 的 6/9/14% 抬升阶梯）
- 选中块前景按亮度自适应（白字 or 同系深墨）

产出的《HAE Creator Design System》是受其启发、面向 AI 软件（对话界面、Prompt/资产管理器、创作工作台）的**原创设计系统**，非该主题复制品。

## 怎么用

**给 AI 编程助手**：把 `HAE Creator Design System V0.3.md` 整份放进项目上下文，或在项目 AGENTS.md 里加一行指针：

```
UI 相关任务必读并遵守 <本仓库路径>/HAE Creator Design System V0.3.md
```

**给人**：直接读终稿；想知道"规则为什么这么定"，查分析报告的数据附录。
